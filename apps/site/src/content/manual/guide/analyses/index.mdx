## Overview

An analysis is the result of a bioinformatic workflow that runs on sample data.

Virtool has two analysis workflows:

- **Pathoscope** finds known viruses.
- **Nuvs** finds novel viruses.

### Analysis jobs

Each analysis runs as a job. An analysis can take minutes or hours. The time
depends on the size and complexity of the sample library.

To monitor analyses, click **Jobs** in the top navigation bar. The list opens
with the running jobs.

The detail page of an analysis job links to the analysis.

### Caching

Nuvs trims sample reads before it uses them. Virtool caches the trimmed reads.
Later Nuvs analyses of the same sample can use the cache. Pathoscope uses
untrimmed reads.

### Reference versions

An analysis uses a [reference](/docs/guide/references) that contains pathogen
sequences. You can edit a reference, and each index build is a new version of
it. Each analysis stays linked to the index version that it used.

A new analysis uses the latest ready index of the reference. To use a newer
version, create a new analysis.

### Subtractions

Subtractions are sets of host or non-pest sequence data. Analyses use them to
remove non-pathogen reads.

For more information, see the [subtractions guide](/docs/guide/subtractions).

## View analyses

1. Open a sample and click the **Analyses** tab.

   This tab shows only when the sample is ready.

2. View the table of analyses.

   The table shows running and completed analyses. Each page shows 25 analyses.

   | Column           | Description                                                                 |
   | ---------------- | --------------------------------------------------------------------------- |
   | **Workflow**     | The workflow name. Click it to open the analysis.                           |
   | **Version**      | The workflow version. This shows **Pending** until the analysis completes.  |
   | **Reference**    | The reference and the index version that the analysis used.                 |
   | **Subtractions** | The subtractions that the analysis used.                                    |
   | **User**         | The user who started the analysis.                                          |
   | **Created**      | The time that the analysis started.                                         |

3. To sort the table, click **Workflow**, **User**, or **Created**.

   By default, the newest analysis shows first.

4. To filter the table, use the **Workflows** and **Users** filters.

The dashboard also shows **Recent Analyses**.

## Create an analysis

You must have write access to the sample to create an analysis.

1. Open a sample and click the **Analyses** tab.

2. Click **Create**.

   The **Analyze** dialog opens.

3. Under **Workflow**, select **Pathoscope** or **Nuvs**.

   Nuvs needs [HMMs](/docs/guide/hmms). If no HMMs are installed, the dialog does
   not show **Workflow**, and the analysis uses Pathoscope.

4. Under **Subtractions**, select the subtractions that you want to use.

   The dialog selects the default subtractions of the sample for you. You can
   remove them.

5. Under **Reference**, select one reference.

   Each reference shows its latest ready index version. If the list is empty,
   build a reference index first.

6. To create more analyses from the dialog, turn on **Create more**.

   The dialog then stays open after each analysis.

7. Click **Create**.

   The new analysis shows in the table. A progress indicator shows until the
   analysis completes.

8. Go to the **Samples** list.

   Each ready sample shows a tag for each workflow. The tag shows the state of
   the workflow for that sample. Click a tag to open the **Analyses** tab of the
   sample.

<Note>
  To analyze many samples at once, select them in the **Samples** list and click
  **Analyze**. The **Quick Analyze** dialog opens. It has the same fields, but it
  does not select default subtractions for more than one sample. [Read more
  about quick analyses](/docs/guide/samples).
</Note>

## Delete an analysis

<Note color="red">

**Analysis deletion is permanent**. A deleted analysis can't be recovered.

</Note>

1. Open the sample and click the **Analyses** tab.

2. In the row of the analysis, click the trash icon.

   The **Delete Analysis** dialog opens.

3. Click **Confirm**.

You must have write access to the sample to delete an analysis. The trash icon
shows only after the job of the analysis stops.

A failed or cancelled analysis stays in the table until a user deletes it. Its
page shows **Analysis failed** or **Analysis cancelled**, with a **View job** link
to the job.

## Interpret Pathoscope

Pathoscope is a workflow that finds known viruses in a sample.

1. View the mapping overview.

   The heading shows the percentage of reads mapped to the reference. This
   percentage includes reads that Virtool later subtracts.

   | Row                            | Description                                                 |
   | ------------------------------ | ----------------------------------------------------------- |
   | **Total reads**                | All reads in the sample.                                    |
   | **Mapped to**                  | The reads mapped to the reference.                          |
   | **Subtracted, mapped better to** | The reads removed because they mapped better to a subtraction. |
   | **Analysed**                   | The reads that remain after subtraction.                    |

   The last two rows show only when the analysis uses a subtraction.

2. View the hit list.

   The list shows each OTU that Pathoscope found. By default, the list shows all
   hits. The list header labels the **Acronym**, **Weight**, **Depth**, and
   **Coverage** columns.

3. Click the name of an OTU to show the coverage charts for its isolates.

   Click a panel of an isolate chart to see the accession, definition, length,
   reads, weight, and coverage of the sequence.

   The dashed line on a chart shows the maximum observed depth. All charts of an
   OTU use this scale.

   - Deep, wide coverage of an isolate often occurs with an infection.
   - Shallow, wide, and broken coverage can occur with contamination between samples on
     the same plate. These hits usually have low weights.
   - High weight with deep coverage in a small area usually comes from low-complexity or
     host-similar regions of the isolate genome. This pattern usually does not show a
     true infection.

4. To hide low-coverage hits, click **Filter**.

   - Turn on **Hide low-coverage OTUs** to hide OTUs.
   - Turn on **Hide low-coverage isolates** to hide isolates in an expanded OTU.
     This switch shows only in the **Charts** view.
   - Use **Hide when coverage less than** to set the limit. The default limit is
     0.50.

As a guide, a dsRNA library can have approximately 5 million reads, but the
percentage of mapped reads is more important. For dsRNA, this percentage can
range from less than 1% to greater than 80%. Greater viral RNA enrichment,
measured by the percentage of mapped reads, reduces the total number of reads
required. For example, 100,000 mapped reads—2% of 5 million—may be sufficient.

| Values   | Description                                                                                                                                                                                                                                                                  |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Coverage | The proportion of genome positions with at least one mapped read. The value for an OTU is the highest coverage of its isolates. As a guide, coverage above 0.5 often occurs with a positive detection, and coverage below 0.2 often occurs with a negative detection.             |
| Depth    | The median number of mapped reads at each genome position.                                                                                                                                                                                                                   |
| Weight   | The calculated proportion of reads mapping to a virus. The weight is roughly proportional to the titre. Higher the titre, higher the weight. As a guide, a weight above 0.001 often occurs with a positive detection.                                                          |

These values are guides, not fixed limits. Use them together with the coverage
charts to make a decision.

### Work with the results

Use the toolbar above the hit list:

- Use the search box to find an OTU by name or acronym.
- Use the sort menu to sort by **Coverage**, **Depth**, **Weight**, or **Name**.
  The button next to it changes the sort direction.
- Click **Charts** or **Table** to change the view. The **Table** view shows the
  values without coverage charts.
- Click **Show Reads** to show read pseudo-counts in place of weights.
- Click **Export** to copy or download results.

The **Export** menu has these options:

- **OTUs** and **Isolates** copy the hits that show on the page, with or without
  headers. You can paste them into a spreadsheet.
- **Excel** and **CSV** download the full analysis.
- **Prefer acronym** names each OTU by its acronym, when it has one.

To copy some hits, select their checkboxes and click **Copy**.

The page address keeps your search, sort, and filter settings. You can share the
link to show the same view.

## Interpret Nuvs

The Basic Local Alignment Search Tool (BLAST) compares sequences with known sequences.

1. Open a sample and click the **Analyses** tab.

2. Click **Nuvs** in the **Workflow** column.

   The list shows assembled sequence fragments (contigs) that may be part of a novel virus.

   In the Nuvs workflow, sample libraries are assembled into contigs. Open
   reading frames (ORFs) are predicted from the contigs, and potential protein
   annotations are assigned using profile HMMs.

3. Click **Filter ORFs** to show ORFs with no HMM annotations.

   ORFs with no significant HMM hits aren't shown by default.

4. Click **Filter Sequences** to show contigs without HMM annotations.

   Contigs with no significant HMM hits aren't shown by default.

5. Click **BLAST at NCBI** to BLAST the contig at NCBI.

6. Wait for the BLAST search to complete.

   Interpreting Nuvs results includes using BLAST to check whether contigs are
   unknown. When the search completes, the **NCBI BLAST** table shows below the
   contig.

Nuvs discovers potential novel viral sequences in a sample library. The workflow:

- Remove known viral and subtraction reads
- Assemble sample reads into long sequences called _contigs_
- Predict open reading frames (ORFs) in the contigs
- Scan the translated ORFs for viral protein motifs using a collection of profile hidden
  Markov models (HMMs)

The Nuvs output lists numbered contigs. Each contig has three values:

| Value   | Description                                                                   |
| ------- | ----------------------------------------------------------------------------- |
| Length  | Number of base pairs in the sequence                                          |
| E-value | The lowest E-value of the HMM matches in the contig. An E-value is the number of matches of this quality that you can expect by chance. A lower value shows a stronger match. |
| ORFs    | The number of open reading frames in the contig with an HMM match             |

The left pane lists the assembled contigs. By default, the list does not show
contigs without ORFs that have significant HMM matches. Click **Filter Sequences**
to show them. The list header shows the number of contigs shown and the total
number. Use <Key>w</Key> and <Key>s</Key> to move through the list.

Select a contig in the left pane to view its details in the right pane. The
contig is shown as a black line with identified ORFs below it. ORFs without
significant HMM matches are hidden by default. Click **Filter ORFs** to show them.

For each ORF with a significant HMM match, the graphic shows its size and
E-value. Click the ORF name to open the HMM. **Families** lists the associated
taxonomic families. The following example shows sequence 37 and its protein
motifs.

![Sequence 37](./nuvs_sequence.png?url)

To send a contig to NCBI for a BLAST search, click **BLAST at NCBI**.
Many contigs derived from known viruses or non-viral sources are assembled. It's
necessary to BLAST significant contigs to ensure they're novel.

Virtool checks the search at intervals. If NCBI has no result after 30 minutes,
the search stops with an error. The result table shows a maximum of 5 hits. To
search again, click **Retry**. The new search replaces the old result.

Use the toolbar above the contig list:

- Use the **Name or family** box to search the contigs.
- Use the sort menu to sort by **Length**, **E-Value**, or **ORFs**.
- Click **Export** to download a FASTA file. The **Contigs** tab exports all
  contigs. The **ORFs** tab exports the proteins of ORFs with HMM matches.

The page address keeps your search, sort, and filter settings.

### Good result

When a BLAST search is completed, a result table is shown below the contig graphic.
This table states the E-value, score, and identity of the viral sequences found on NCBI.

![NCBI BLAST](./nuvs_blast_pvev.png?url)

The E-values, scores, and identities in the BLAST results show high-quality matches.
This indicates that these contigs don't represent novel viral genomes.
However, the Virtool reference does not contain these sequences. Nuvs removes reads
that map to the reference before assembly, so these reads stayed in the sample and
formed contigs.

This sample contains Phaseolus vulgaris endornavirus as an internal control introduced
during nucleic acid extraction. This explains the identification of Phaseolus vulgaris
alphaendornavirus 2 in the sample.

Another contig has the following BLAST results:

![NCBI BLAST 2](./nuvs_blast_prunus.png?url)

The high E-value for the HMM match (0.39) indicates the capsid protein match is
tenuous.

Additionally, the BLAST results show that the contig is strongly related to _Prunus dulcis_
(almond). The E-values for all accessions are zero and the scores and identities are
high.

This sample is from a _Prunus_ host. The most likely source of this contig is the host
genome.

This interpretation assumes that the _Prunus dulcis_ sequences used to build the HMM
reference are actually from the host. It's important to bear in mind that reference
databases aren't reliable and may contain viral nucleotide and protein sequences
mis-annotated as originating from the host.

### Suspicious result

The result view below suggests a potential novel virus.

![NCBI BLAST 4](./nuvs_blast_novel.png?url)

The HMM match has a low E-value of 5e-96, indicating a strong match.

The NCBI BLAST results suggest that this contig could represent a novel virus. The contig has
significant BLAST hits to known viruses (for example, Nectarine marafivirus M), but the
identities are low (0.73–0.76). This low identity suggests that the contig may
represent a novel virus dissimilar to related known viruses.

The sequence is large (6382 bp), so it is worth assembling to find more about the viral
genome.

### Non-viral result

This contig represents likely bacterial contamination from the field or laboratory:

![NCBI BLAST 6](./nuvs_bacteria.png?url)

The BLAST results for this contig show hits for bacterial species, all with
identities of 1.00. Based on their scores, they're all similar matches. Knowing that
these bacterial species aren't commonly found in plants, specifically in _Malus_, this
is most likely a case of contamination.

The following contig demonstrates contamination from a lab technician or field collector:

![NCBI BLAST 6](./nuvs_human.png?url)

The E-value for the HMM match is weak, indicating that the annotation is
unreliable.

Further, the BLAST results for this contig reveal strong matches to _Homo sapiens_ (human)
and _Pan troglodytes_ (chimpanzee). Given this information, this is likely a case of
human contamination.

#### Next steps

If a suspicious result is found during interpretation of Nuvs results, it's important to
further characterize the sequence using other bioinformatic tools with help from a
bioinformatician. Nuvs makes a best effort to detect **potential** novel viral sequences
automatically. Further manual work is almost always required to produce a
full-length genome sequence.

In the common case that new variants of known viruses are found, adding them to a virus
reference in Virtool is beneficial for future runs using Pathoscope. Doing so saves time
analyzing data as more sequence information is available and also presents users with
more accurate results.
