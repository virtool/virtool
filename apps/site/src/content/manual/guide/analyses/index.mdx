## Overview

An analysis is the result of a bioinformatic workflow that runs on sample data.

Virtool has two analysis workflows:

- **Pathoscope** finds known viruses.
- **Nuvs** finds novel viruses.

### Analysis jobs

Each analysis runs as a job. An analysis can take minutes or hours. The time
is longer for a large or complex sample library.

To monitor analyses, click **Jobs** in the top navigation bar. By default, the
list shows only pending and running jobs. To show other jobs, use the **State**
filter.

The detail page of an analysis job links to the analysis.

### Caching

Nuvs trims sample reads before it uses them. Virtool caches the trimmed reads.
Later Nuvs analyses of the same sample can use the cache. Pathoscope uses
untrimmed reads.

An administrator sets the maximum size of the cache. See
[Caching](/docs/guide/administration#caching).

### Reference versions

An analysis uses a [reference](/docs/guide/references) that contains pathogen
sequences. You can edit a reference, and each index build is a new version of
it. Each analysis stays linked to the index version that it used.

A new analysis uses the latest ready index of the reference. To use a newer
version, create a new analysis.

### Subtractions

Subtractions are sets of host or non-pathogen sequence data. Analyses use them
to remove reads that are not from a pathogen.

For more information, see the [subtractions guide](/docs/guide/subtractions).

## View analyses

1. Open a sample and click the **Analyses** tab.

   Virtool shows this tab only when the sample is ready.

2. View the table of analyses.

   The table shows running and complete analyses. Each page shows 25 analyses.
   The count above the table shows how many analyses match your filters.

   | Column           | Description                                                                  |
   | ---------------- | ---------------------------------------------------------------------------- |
   | **Workflow**     | The workflow name. Click it to open the analysis.                            |
   | **Version**      | The workflow version. This shows **Pending** until the analysis is complete. |
   | **Reference**    | The reference and the index version that the analysis used.                  |
   | **Subtractions** | The subtractions that the analysis used.                                     |
   | **User**         | The user who started the analysis.                                           |
   | **Created**      | The time that the analysis started.                                          |

3. To sort the table, click **Workflow**, **User**, or **Created**.

   By default, the table shows the newest analysis first.

4. To filter the table, use the **Workflows** and **Users** filters.

   If no analyses match, click **Clear filters**.

The dashboard also shows **Recent Analyses**.

## Create an analysis

You must have write access to the sample to create an analysis.

1. Open a sample and click the **Analyses** tab.

2. Click **Create**.

   The **Analyze** dialog opens.

3. Under **Workflow**, select **Pathoscope** or **Nuvs**.

   Nuvs cannot run without [HMMs](/docs/guide/hmms). If Virtool has no HMMs, the
   dialog does not show **Workflow**, and the analysis uses Pathoscope. The
   **Analyses** tab then shows **HMM data is not installed**, with an **Install
   HMMs** link.

4. Under **Subtractions**, select the subtractions that you want to use.

   The dialog selects the default subtractions of the sample for you. You can
   remove them.

5. Under **Reference**, select one reference.

   Each reference shows its latest ready index version. If no reference has a
   ready index, the dialog shows **No references found**. Build a reference
   index first.

6. Click **Create**.

   The dialog shows the number of jobs that Virtool will start. The table shows
   the new analysis, with a progress indicator until the analysis is complete.

To create more analyses without closing the dialog, turn on **Create more**
before you click **Create**.

After the analysis is created, go to the **Samples** list. Each ready sample
shows a tag for each workflow. The tag shows the state of the workflow for that
sample. Click a tag to open the **Analyses** tab of the sample.

<Note>
  To analyze many samples at once, select them in the **Samples** list and click
  **Analyze**. To analyze one sample, click **quick analyze** in its row. The
  **Quick Analyze** dialog opens. It has the same fields, but it does not select
  default subtractions for more than one sample. [Read more about quick
  analyses](/docs/guide/samples).
</Note>

## Delete an analysis

<Note color="red">

**You cannot recover a deleted analysis.**

</Note>

You must have write access to the sample to delete an analysis. Virtool shows
the **Delete** button only after the job of the analysis stops.

1. Open the sample and click the **Analyses** tab.

2. In the row of the analysis, click **Delete**.

   The **Delete Analysis** dialog opens.

3. Click **Confirm**.

A failed or cancelled analysis stays in the table until a user deletes it. Its
page shows **Analysis failed** or **Analysis cancelled**, with a **View job** link
to the job.

## View Pathoscope results

1. Open a sample and click the **Analyses** tab.

2. Click **Pathoscope** in the **Workflow** column.

The page heading shows the workflow and the sample name. Below it, Virtool shows
the user who started the analysis, the start time, and the workflow version.
Click the start time or the version to copy it.

An analysis that is not complete shows **Analysis in progress**.

### Mapping overview

The heading shows the percentage of reads mapped to the reference. This
percentage includes reads that Virtool later subtracts. A bar shows the mapped
reads as a part of all reads. Blue shows the analysed reads. Orange shows the
subtracted reads.

| Row                              | Description                                                    |
| -------------------------------- | -------------------------------------------------------------- |
| **Total reads**                  | All reads in the sample.                                       |
| **Mapped to**                    | The reads mapped to the reference. The row names the reference and its index version. |
| **Subtracted, mapped better to** | The reads removed because they mapped better to a subtraction. |
| **Analysed**                     | The reads that remain after subtraction.                       |

The table shows the last two rows only when the analysis uses a subtraction.

### Hit list

The list shows each OTU that Pathoscope found. By default, the list shows all
hits. The list header shows the number of hits. When a search or filter hides
hits, the header shows the number of visible hits and the total.

Each hit shows its values in columns. The **Acronym** column shows only when an
OTU has an acronym.

| Value    | Description                                                                                                                       |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Weight   | The calculated proportion of reads that map to a virus. The weight is approximately proportional to the titre.                     |
| Depth    | The median number of mapped reads at each genome position.                                                                        |
| Coverage | The proportion of genome positions with at least one mapped read. The value for an OTU is the highest coverage of its isolates.   |

Each hit shows a coverage chart for the OTU. The chart shows the read depth
across the genome. A segmented genome has one panel for each segment.

Click the name of an OTU to show the coverage charts for its isolates. Each
isolate shows its own weight, depth, and coverage. Click a panel of an isolate
chart to see the sequence details: the accession, definition, length, reads,
weight, and coverage. The accession links to NCBI.

A panel with no reads shows **no reads**. A panel for a segment that the isolate
does not have shows **not in this isolate**.

The dashed line on a chart shows the maximum depth of the OTU. The number at the
top left of the chart shows this depth. All charts of the OTU use this depth as
the top of their scale.

### Filter, sort, and export

To hide low-coverage hits, click **Filter**. The filter has these settings:

- **Hide low-coverage OTUs**: hides OTUs with coverage less than the limit.
- **Hide low-coverage isolates**: hides isolates with coverage less than the
  limit. This switch shows only in the **Charts** view.
- **Hide when coverage less than**: sets the limit. The default is 0.50. You can
  change the limit only when a switch is on.

When a filter is on, the **Filter** button shows a blue dot.

Use the toolbar above the hit list:

- Use the search box to find an OTU by name or acronym.
- Use the sort menu to sort by **Coverage**, **Depth**, **Weight**, or **Name**.
  By default, the list is sorted by coverage. Click **Sort ascending** or **Sort
  descending** next to the menu to change the sort direction.
- Click **Charts** or **Table** to change the view. The **Table** view shows the
  values without coverage charts.
- Click **Show Reads** to show read pseudo-counts in place of weights.
- Click **Export** to copy or download results.

The **Export** menu has these options:

- Under **Copy**, **OTUs** and **Isolates** copy the hits that the page shows,
  with or without headers. You can paste them into a spreadsheet.
- Under **Download**, **Excel** and **CSV** download the full analysis.
- **Prefer acronym** puts the acronym of an OTU in the export in place of its
  name, if the OTU has an acronym. Virtool keeps this setting for your account.
- **Settings** opens your [Pathoscope export
  settings](/docs/guide/account#pathoscope-export). These settings set the
  columns and their order in copies and downloads.

To copy some hits, select their checkboxes and click **Copy**. To select all
visible hits, select the checkbox in the list header.

The copy options show only on a secure (HTTPS) connection.

The page address keeps your search, sort, and filter settings. You can share the
link to show the same view.

## Interpret Pathoscope

Use the mapped reads, the values of each hit, and the coverage charts together
to make a decision.

### Mapped reads

As a guide, a dsRNA library can have approximately 5 million reads, but the
percentage of mapped reads is more important. For dsRNA, this percentage can
be less than 1% or more than 80%. The percentage of mapped reads shows the
enrichment of viral RNA. When the enrichment is high, fewer total reads are
necessary. For example, 100,000 mapped reads (2% of 5 million) can be enough.

### Hit values

- A coverage above 0.5 often occurs with a positive detection. A coverage below
  0.2 often occurs with a negative detection.
- A weight above 0.001 often occurs with a positive detection. A higher titre
  gives a higher weight.

These values are guides, not fixed limits. Use them together with the coverage
charts to make a decision.

### Coverage patterns

- Deep, wide coverage of an isolate often occurs with an infection.
- Shallow, wide, and broken coverage can occur with contamination between
  samples on the same plate. Hits with this pattern usually have low weights.
- Deep coverage in a small area is usually non-specific mapping. Reads can map
  to low-complexity or host-similar regions of the isolate genome. This pattern
  usually does not show a true infection. **Depth** is a median, so it can be 0
  when the chart shows a high peak.

## View Nuvs results

Nuvs finds possible novel viral sequences in a sample library. The workflow does
these steps:

1. It removes known viral reads and subtraction reads.
2. It assembles sample reads into long sequences called _contigs_.
3. It predicts open reading frames (ORFs) in the contigs.
4. It scans the translated ORFs for viral protein motifs. It uses a collection of
   profile hidden Markov models (HMMs) for this scan.

To view the Nuvs results of a sample:

1. Open a sample and click the **Analyses** tab.

2. Click **Nuvs** in the **Workflow** column.

### Contig list

The left pane shows a list of the assembled contigs that can be part of a novel
virus. Each contig has a name, such as **Sequence 8**, and three values:

| Value   | Description                                                                   |
| ------- | ----------------------------------------------------------------------------- |
| Length  | The number of base pairs in the sequence.                                     |
| E-value | The lowest E-value of the HMM matches in the contig. An E-value is the number of matches of this quality that you can expect by chance. A lower value shows a stronger match. |
| ORFs    | The number of open reading frames in the contig that have an HMM match.       |

By default, the list shows only contigs that have an HMM match. To show all
contigs, set **Filter Sequences** to off. The list header shows the number of
visible contigs and the total number of contigs. Use <Key>w</Key> and <Key>s</Key>
to move through the list.

### Contig detail

Select a contig in the left pane to see its details in the right pane. The pane
shows the contig length, the number of ORFs with an HMM match, and the E-value
of the contig. Below these values, it shows the contig as a line, with the
identified ORFs below it. Each ORF is an arrow that shows its position and
strand. By default, the pane shows only ORFs that have an HMM match. To show
all ORFs, set **Filter ORFs** to off.

For each ORF with an HMM match, the pane shows the HMM name, the length of the
ORF in base pairs, and the E-value. Click the HMM name to open the HMM. An ORF
with no HMM match shows **Unannotated**. **Families** shows the virus families
of all HMMs that match the contig.

The example shows Sequence 8. The contig is 5,460 bp long. Four ORFs match
HMMs: **Replicase**, **Triple Gene Block Protein 1**, **Triple Gene Block
Protein 2**, and **Unknown Similar To AMEVITR04**. The E-value of the replicase
match is 0, so the E-value of the contig is also 0.

![Sequence 8, with four ORFs that match HMMs](./nuvs_sequence.png?url)

### BLAST

The Basic Local Alignment Search Tool (BLAST) compares sequences with known
sequences.

1. Select a contig.

2. Click **BLAST at NCBI**.

3. Wait until the BLAST search is complete.

While the search runs, the page shows **BLAST in progress**, with the request ID
(RID) of the search. The RID links to the search at NCBI. Virtool checks the
search at intervals, and shows the time of the last and the next check.

If NCBI has no result after 30 minutes, the search stops with an error. To
search again, click **Retry**. The new search replaces the old result.

When the BLAST search is complete, the page shows the **NCBI BLAST** table
below the contig. For each hit, the table shows the **Accession**, **Name**,
**E-value**, **Score**, and **Identity**. The accession links to NCBI. The table
shows a maximum of 5 hits. If NCBI finds no hits, the page shows **No BLAST hits
found**.

### Filter, sort, and export

Use the toolbar above the contig list:

- Use the **Name or family** box to search the contigs.
- Use the sort menu to sort by **Length**, **E-Value**, or **ORFs**.
- Click **Export** to download a FASTA file. In the **Export Analysis** dialog,
  select **Contigs** or **ORFs**, then click **Download**. **Contigs** exports
  all contigs. **ORFs** exports the proteins of ORFs with HMM matches. The dialog
  shows an example of the FASTA header for each option.

The page address keeps your search, sort, and filter settings.

## Interpret Nuvs

Nuvs assembles many contigs from known viruses or non-viral sources. Use BLAST
to find if a contig with an HMM match is novel.

### BLAST results

Most contigs do not come from novel viruses. Use the BLAST hits to find the
source of a contig:

| BLAST hits                                             | Likely source                                                                                                                              |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| High identity to a known virus                         | A known virus that is not in the reference. Nuvs removes reads that map to the reference before assembly, so the reads of this virus stay. |
| High identity to the host                              | The host genome. A weak HMM match often occurs with this result.                                                                           |
| Low identity to known viruses, with a strong HMM match | A possible novel virus.                                                                                                                    |
| High identity to bacteria, humans, or other non-hosts  | Contamination from the field or the laboratory.                                                                                            |

Public databases can contain sequences with incorrect annotations. For example,
a viral sequence can have a host annotation.

### Next steps

Nuvs finds only possible novel viral sequences. To confirm a possible novel
virus, examine the contig with other bioinformatic tools. A bioinformatician can
help. Usually, you must do more work to get a full-length genome sequence.

If you find a new variant of a known virus, add it to a reference. Pathoscope
can then find it in later analyses.
