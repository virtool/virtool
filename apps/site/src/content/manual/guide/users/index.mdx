User accounts control access to Virtool. They control which actions users can do and
which data they can access.

## Concepts

### Ownership

When a user creates a sample or a reference, that user becomes its owner. The owner of
a sample or reference always has all rights on it.

### Rights

Rights are properties of samples and references. They control what specific users or
groups can do with a sample or reference.

Full administrators have all rights on all samples and references.

### Permissions

Permissions control which instance-wide actions users can do. Users get permissions
from the groups they are members of. You can't set permissions for one user.

| Permission           | Description                    |
| -------------------- | ------------------------------ |
| `cancel_job`         | Cancel running jobs            |
| `create_ref`         | Create new references          |
| `create_sample`      | Create new samples             |
| `modify_hmm`         | Install and manage HMM data    |
| `modify_subtraction` | Create and modify subtractions |
| `remove_file`        | Delete uploaded files          |
| `remove_job`         | Delete job records             |
| `upload_file`        | Upload files                   |

### Groups

A group gives rights and permissions to more than one user. Members of a group get the
rights and permissions of the group.

### Administrator roles

A user can have one administrator role. A user without a role is a limited user.

| Role     | What the role can do                                        |
| -------- | ----------------------------------------------------------- |
| Full     | Manage who is an administrator and what they can do.        |
| Settings | Manage [instance settings](/docs/guide/administration).     |
| Users    | Create user accounts. Control activation of user accounts.  |
| Base     | Manage HMMs and common references. View and cancel any job. |

Each role can also do everything that the roles below it can do.

Administrator roles also give permissions. All administrators have the `cancel_job`,
`create_ref`, `modify_hmm`, and `remove_job` permissions. Full administrators have all
permissions.

Only a full administrator can assign or remove an administrator role, or change a user
who has an administrator role. You can't change your own role.

## Open user administration

1. Click your avatar at the right of the main navigation bar.
2. Click **Administration**.
3. In the sidebar, click **Users**.

You must have the Users, Settings, or Full administrator role to see **Administration**.

The users list shows the handle, email, role, primary group, and status of each user. The
status is **Active**, **Invited**, or **Deactivated**.

To find users, type a handle or email address in the search field. To filter the list,
use the **Role** and **Status** filters. Click a column heading to sort the list by that
column.

Click a handle to open the user's details.

## Create a user

When you create a user, Virtool makes an invited account and an invitation link. The user
opens the link and [chooses a handle and a password](/docs/guide/sign-in#accept-an-invitation).

1. Click **Create**.
2. Type the email address of the user under **Email**.
3. Optional: under **Groups**, add the user to groups. Click **Primary** beside a group to
   make it the user's primary group.
4. Optional: select an **Administrator role**. Only full administrators see this field.
5. Under **Invitation delivery**, select one option:
   - **Email invitation**: Virtool sends the link to the email address. This option is
     available only if [email delivery](/docs/guide/administration#email-delivery)
     is set up.
   - **Create shareable link**: you send the link to the user yourself.
6. Click **Save**.
7. If you selected **Create shareable link**, copy the link and send it to the user.
   Virtool shows the link only one time.
8. Click **Done**.

An invitation link expires after 72 hours.

## Manage an invitation

Open the details of an invited user to see the status of the invitation. The
**Invitation** section shows:

- **Status**: **Pending**, **Expired**, **Replaced**, or **Accepted**.
- **Delivery**: **Shared link**, **Email queued**, **Email sent**, or **Email failed**.
- When the invitation was sent, and when it expires.

### Reissue an invitation

Reissue an invitation if it expired, if the email failed, or if the user lost the link.

1. Click **Reissue**.
2. Select **Email invitation** or **Create shareable link**.
3. Click **Reissue**.

The old link stops working.

### Delete an invited user

You can delete a user who did not accept the invitation.

1. Under **Danger Zone**, click **Delete**.
2. Click **Confirm**.

The invitation link stops working.

## Change a user's handle

1. Open the user's details.
2. Under **Change Handle**, type the new handle.
3. Click **Save**.

The handle is the name that the user signs in with. Tell the user about the change.

Virtool can ask you to confirm your identity before it changes a user.

## Help a user recover access

If a user forgets their password, create a password reset link for them.

1. Open the user's details.
2. Under **Password reset link**, click **Create reset link**.
3. If [email delivery](/docs/guide/administration#email-delivery) is set up, Virtool
   sends the link to the user. If it is not set up,
   copy the link and send it to the user yourself.

The link works one time. A link that you copy expires after one hour. A link that
Virtool sends by email expires after 7 hours. When you create a new link, the previous
link stops working. Virtool shows the link only one time.

The user then [chooses a new password](/docs/guide/sign-in#choose-a-new-password).

To stop all of the user's reset links, click **Revoke links**.

## Change a user's groups

The groups of a user change which permissions the user has. They can also change which
rights the user has on samples and references.

1. Open the user's details.
2. Under **Groups**, select a group in the **Add group** field.

To remove the user from a group, click **Remove** (the X) beside the group.

The **Permissions** list shows the permissions that the user has now. It updates when you
change the groups.

## Change a user's primary group

When a user creates a sample, Virtool can give the sample to the user's primary group.
You can [configure](/docs/guide/samples/#settings) how Virtool assigns a group to new
samples.

The primary group must be one of the user's groups.

1. Open the user's details.
2. Under **Groups**, click **Primary** beside the group.

To remove the primary group, click **Primary** beside the current primary group.

## Change a user's administrator role

You must be a full administrator.

1. Open the user's details.
2. Under **Administrator Role**, select a role.

To remove the role, click **Remove administrator role** (the trash icon) beside the role.

## Deactivate a user

A deactivated user can't use Virtool.

1. Open the user's details.
2. Under **Danger Zone**, click **Deactivate**.

To restore access, click **Activate**.

## Reset two-factor authentication

Reset two-factor authentication for a user who lost their authenticator app and their
recovery codes. You must be a full administrator. You can't reset your own two-factor
authentication here.

1. Open the user's details.
2. Under **Danger Zone**, click **Reset**.
3. Click **Confirm**.

Virtool removes the authenticator and recovery codes of the user and signs the user out
everywhere. If your instance [requires two-factor
authentication](/docs/guide/administration#security) and the user has no
passkey, the user must set it up again at the next sign-in.

## Revoke a user's access

Revoke access if a user's account is compromised. You can't revoke your own access.

1. Open the user's details.
2. Under **Danger Zone**, click **Revoke**.
3. Click **Confirm**.

Virtool signs the user out everywhere. The password, API keys, passkeys, two-factor
authentication, and links of the user stop working. The email address of the user is no
longer verified. Virtool does not tell the user.

To restore access, create a [password reset link](#help-a-user-recover-access) and send
it to the user through a channel that you trust.

## Manage groups

To open groups, go to **Administration**, then click **Groups** in the sidebar.

The groups are in a list at the left. Click a group to see its permissions and members.

### Create a group

1. Click **Create**.
2. Type a name for the group.
3. Click **Save**.

### Rename a group

1. Select the group.
2. Click the group name at the top of the page.
3. Type the new name, then press <kbd>Enter</kbd>.

### Change a group's permissions

1. Select the group.
2. Under **Permissions**, select or clear each permission.

Virtool saves each change immediately. All members of the group get the new permissions.

The **Members** list shows the users in the group. To add or remove members, change the
[groups of each user](#change-a-users-groups).

### Delete a group

1. Select the group.
2. Click **Delete**.
3. Click **Confirm**.

Samples that belonged to the group have no group after you delete it. Virtool removes the
rights that the group had on references.
